# Gexus

Production landing page for Gexus, an AI native CAD platform.

## Requirements

**Node.js 18.18 or newer** (the Next.js 15 minimum). If `npm run dev` refuses
to start, check `node -v` first.

```bash
npm install
npm run dev        # http://localhost:3000
npm run build
npm run start
npm run lint
npm run typecheck
npm run art        # regenerate the SVG artwork in public/images
```

## Stack

Next.js 15 (App Router), TypeScript, Tailwind CSS. That is the whole runtime
list. There is no animation library, no 3D library and no scroll library on
the client.

| Route | Page JS | First load JS |
| --- | --- | --- |
| `/` | 19.2 kB | 122 kB |

Of that 122 kB, 103 kB is the shared React and Next runtime. Everything this
site adds on top is under 20 kB.

## How the speed is achieved

**No animation library.** Scroll reveals are one shared `IntersectionObserver`
in `components/RevealObserver.tsx` that adds `.is-visible`; the transitions
themselves live in `app/globals.css`. Sections mark themselves up with
`<Reveal>` and `<RevealGroup>`, which are server components that only stamp a
data attribute. Hovers, the mobile menu, the footer accordion and the quote
carousel are all CSS.

**No 3D on the client.** The hero part used to be a live React Three Fiber
scene, which cost roughly half a megabyte of JavaScript to draw one object
that never changes. It is now a render of that scene shipped as an image. The
float, the two degree tilt and the parallax are CSS transforms driven by four
custom properties. The original scene is archived at
`art/hero-lattice-scene.tsx` and excluded from the build.

**Server components by default.** Every section renders on the server. Only
four leaves are client components, each for a single piece of state:
`Navbar`, `ConceptRail`, `Testimonials`, `FooterAccordion`, plus `HeroArt` for
the pointer tilt and `ParticleWave` for its canvas.

**Artwork is static files.** Everything in `public/images` is generated by
`scripts/generate-art.mjs` and served as a plain cacheable file, so it never
enters the HTML or the RSC payload.

**One font file.** Inter as a variable font, latin subset, self hosted by
`next/font`.

## Crawlability

Every headline, paragraph, quote, figure caption and navigation link is in the
server rendered HTML, so a crawler that does not execute JavaScript still sees
the entire page. Specifically:

- Reveal animations only change `opacity` and `transform`. The text is always
  in the document. A `<noscript>` block in the layout paints it even if
  scripting never runs.
- All four testimonials stay mounted; only opacity changes between them.
- The footer accordion keeps every link in the DOM whether it is open or not.
- Headings run `h1` then `h2` then `h3` with no skipped levels.
- Every image has descriptive alt text naming what the part actually is.
- `app/layout.tsx` emits Organization, WebSite and SoftwareApplication JSON LD.
  There is deliberately no review or rating markup, since there is nothing
  real to back it.
- `public/llms.txt` gives AI crawlers a plain text summary of the product.
- `app/robots.ts` and `app/sitemap.ts` generate `/robots.txt` and
  `/sitemap.xml`.

## Artwork

`npm run art` regenerates every SVG in `public/images` from
`scripts/generate-art.mjs`. The geometry for the drone arm bracket is defined
once at the top of that file and reused across the concept variants and the
process strip, so the same part is recognisable at every stage.

| File | What it shows |
| --- | --- |
| `hero-lattice.webp` | The generated bracket, load paths resolved into a woven lattice |
| `concept-lattice.svg` | Triangulated lattice infill, the stiffest option |
| `concept-ribbed.svg` | Straight radial ribs, the quickest to machine |
| `concept-shell.svg` | Solid shell, the cheapest to tool |
| `step-sketch.svg` | Dimensioned concept wireframe |
| `step-model.svg` | Finished solid model |
| `step-stress.svg` | Stress plot with a legend in megapascals |
| `step-machining.svg` | Five axis mill cutting the part |
| `step-inspection.svg` | Probe points and a tolerance callout |
| `lab.svg` | Robotics assembly cell |
| `emblem.svg` | The chrome emblem on its plinth |

The hero image is the one asset not produced by that script. To regenerate it,
restore the `three` and `@react-three/fiber` dependencies, mount
`art/hero-lattice-scene.tsx`, and capture the canvas with
`preserveDrawingBuffer` enabled.

## The wordmark

`components/ui/Wordmark.tsx` draws GEXUS as custom geometry rather than
setting it in a font. The letterforms are a geometric extended sans in the
Eurostile Extended and Microgramma tradition: a 118 by 100 grid per glyph, one
uniform stroke weight of 19 units, rounded square corners at 20 units on the
outside and 9 in the counters, 5 unit chamfers on the terminals, and 46 units
of tracking between glyphs.

Each glyph is a list of vertices with a per corner radius. `roundedPath` trims
each vertex back along both adjacent edges and bridges them with a quadratic
through the original corner, which lands slightly squarer than a true arc and
gives the superellipse feel these forms want. Adjusting a letter means moving
a number in the vertex list, not editing path data.

The finish is layered: a four step extrusion behind the face, a titanium
gradient on the face, a two tone bevel stroked inside the glyph clip (nudged
down for the lit top edges, up for the shaded bottom ones), and a specular
sweep across the upper third.

Two tones ship. `dark` is the glossy black titanium the brief calls for and is
used in the nav. `light` is the same metal read for dark surfaces and is used
in the footer, where black on black would disappear. The path data is defined
once per instance and referenced with `<use>`, so it appears in the document a
single time rather than once per finish layer.

## The metallic finish

`.chrome` in `app/globals.css` fills headings with a gradient through
`background-clip: text`. The ramp deliberately stays in the dark half of the
scale: a light chrome gradient on a white page drops below AA contrast, while
this one keeps headings legible and reads the light bands as reflections. Text
stays selectable and crawlable either way. There are fallbacks for browsers
without `background-clip: text`, for print, and for forced colours mode.

`.chrome-light` is the inverse, for dark surfaces. `.metal-surface` and
`.metal-rule` cover the plate fills and hairlines, and the primary button
carries a metallic top highlight and an inset ring.

## Copy

All visible copy lives in `lib/site.ts`. House style, please keep to it:

- Write like an engineer talking to another engineer. Concrete over grand.
- **No hyphens, en dashes or em dashes in visible text.** Recast the sentence
  instead. "AI native", not "AI-native". "37% lighter", not "-37%".
- Prefer specific claims with numbers over adjectives.

## Motion and accessibility

Everything is gated on `prefers-reduced-motion`: reveals resolve instantly,
the float and tilt stop, and transitions collapse. The page is keyboard
navigable, has a skip link, uses semantic landmarks and labelled controls, and
holds AA contrast throughout.

Note that smooth scroll is now plain CSS `scroll-behavior`. The Lenis
dependency was removed; it hurt input responsiveness for a subtle effect.

- Open Graph currently points at the hero render. Swap in a purpose built
  1200x630 card if you want one.
- Wire `#access` to the real early access form.
